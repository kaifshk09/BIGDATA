About PhishGuard

A college mini project that helps users recognise the URL patterns phishers rely on — and is honest about what heuristics can and cannot tell you.

{# -------------------------------------------------------- How it works #}

Under the hood

How the analysis works

  1. 1

    Normalise & validate

    The URL is trimmed, given an https:// prefix when the scheme is missing, and parsed with Python's urllib.parse. Unsupported schemes, control characters, invalid ports and bare words are rejected.

  2. 2

    Extract features

    Scheme, hostname, IP status, subdomain depth, punycode, hyphens, port, path keywords, query size and file extensions are inspected. No network request is performed — there is no DNS lookup, HTTP call or redirect follow.

  3. 3

    Add documented points

    Each heuristic adds a fixed number of points, listed in the table below. The total is capped at 100 and mapped to a verdict, so the same URL always produces the same result.

  4. 4

    Explain & recommend

    Every point is displayed next to a plain-English explanation, followed by practical next steps. Results for valid URLs are saved in SQLite so they can be reviewed later.

Privacy by design: the server never visits the submitted URL, follows its redirects or executes its contents. Only the text you paste is analysed and stored.

{# --------------------------------------------------------------- Weights #}

Transparency

Heuristic rules and weights

Points are fixed and documented in core/analysis.py. Weights are an educational judgement, not a calibrated probability.

High-impact signals

  • Deceptive @ in URL+40
  • Punycode (IDN) hostname+30
  • Hex / integer host (0x7f…)+30
  • IP address as host+25
  • Brand name in a different domain+20
  • Username & password embedded+20
  • Excessive subdomains+15
  • Risky file extension+15
  • Private / reserved IP address+15

Moderate signals

  • HTTP instead of HTTPS+10
  • URL longer than 100 characters+10
  • Hostname longer than 30 characters+12
  • Unusual port+12
  • Many hyphens in hostname+10
  • Host looks numeric (192.168.ten.1)+10
  • Double URL encoding+10
  • Security keyword in hostname+10
  • Security keyword in path+8
  • Six or more query parameters+8
  • Backslash / encoded slash+8
  • Hosted on free document service+8
  • URL shortener+5
  • Embedded URL in query string+5

Informational signals (HTTPS present, www. prefix) never change the score, because phishing sites also use HTTPS.

Technology stack

  • Testingunittest / pytest

Project architecture

  • app.pyRoutes, error handlers, app factory
  • core/analysis.pyHeuristic scoring engine
  • core/database.pySQLite access layer
  • core/security.pyCSRF protection
  • templates/Jinja2 views and macro partials

Known limitations

  • Heuristics only — this is not a trained machine-learning model or a threat-intelligence feed.
  • Scores are not probabilities and are not calibrated against a labelled dataset.
  • The tool does not check page content, domain age, DNS records, certificates or blocklists.
  • Legitimate URLs can trigger warnings, and well-crafted phishing URLs can avoid every rule.
  • “Lower Risk” means “no rule fired”, never “verified safe”.
  • The history database is shared by everyone using this computer.

Future scope

  • Train a model on a labelled phishing URL dataset.
  • Optional integration with a trusted threat-intelligence API.
  • WHOIS / domain-age checks through a reviewed, rate-limited service.
  • User accounts and per-user history.
  • CSV / PDF report export for the college demonstration.
